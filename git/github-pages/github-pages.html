GitHub Pages

 

 

 

GitHub Pages — это бесплатный сервис статического хостинга от платформы GitHub, который позволяет превратить обычный репозиторий с кодом в полноценный работающий веб-сайт. Для запуска страницы не нужно арендовать сервер, настраивать базы данных или покупать хостинг: достаточно загрузить файлы проекта в репозиторий и активировать функцию в настройках.

Сервис работает исключительно со статическими сайтами, построенными на базе HTML, CSS и JavaScript. Он идеально подходит для публикации сайтов-визиток, личных портфолио, блогов, лендингов, документации к проектам или простых браузерных приложений. При этом на GitHub Pages нельзя запустить серверный код вроде PHP, Python или Node.js, а также напрямую подключить классические базы данных.

По умолчанию каждому опубликованному проекту выделяется бесплатный домен вида имя_пользователя.github.io/название_репозитория с автоматически подключённым защищённым протоколом HTTPS. Если стандартный адрес не подходит, к сайту можно легко привязать собственный купленный домен через настройку DNS-записей.

Главное удобство платформы заключается в автоматическом обновлении сайта при каждом изменении кода в репозитории. Как только разработчик отправляет свежий коммит через команду git push, система сама пересобирает проект и публикует актуальную версию страницы в интернете в течение пары минут.

Помимо загрузки готовой вёрстки, GitHub Pages поддерживает генераторы статических сайтов, такие как Jekyll, Hugo или React-сборки, с помощью инструментов автоматизации GitHub Actions. Это позволяет создавать сложные многостраничные ресурсы и блоги на основе обычных текстовых файлов в формате Markdown без ручного написания каждого HTML-документа.

Да, вы можете назвать папку с нижнего подчёркивания (например, _utils или _temp) — для самого Git и GitHub это абсолютно валидный символ, и папка будет отображаться наверху списка файлов. Однако есть несколько важных нюансов в зависимости от того, какие инструменты вы используете: GitHub Pages (Jekyll): по умолчанию Jekyll игнорирует папки, начинающиеся с _ (кроме системных вроде _posts или _includes), и не добавляет их в итоговый сайт. Если вы не используете GitHub Pages для сборки сайта, это ни на что не повлияет.
